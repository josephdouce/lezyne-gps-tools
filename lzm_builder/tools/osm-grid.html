📖 Detailed Instructions

🎯 What This Tool Does

This tool generates a comprehensive download strategy for creating offline maps of large regions (countries, states, provinces). It divides your selected area into a grid of 0.20° × 0.20° degree boxes and creates a bash script to download OpenStreetMap highway data for each square from the Overpass API. This data can then be converted into Lezyne LZM offline map files.

🚀 Complete Workflow

Step 1: Generate Download Script

  1. Click the 🛑 button to enter polygon mode
  2. Drag the octagon vertices to cover your desired region
  3. Ensure polygon remains convex (tool will warn if not)
  4. Copy the generated bash script from the text area
  5. Save to a file: download_region.sh

Step 2: Download OSM Data

# Create and enter download directory
mkdir my_region_osm && cd my_region_osm

# Use vi or nano to create the script file

# Make script executable and run
chmod +x download_region.sh
./download_region.sh

Why 30-second delays? The Overpass API has rate limits to prevent server overload. The 30-second delay ensures we respect these limits and maintain good citizenship with the free service.

Resume capability: If downloads are interrupted, simply re-run the script. It automatically skips files that already exist and are larger than 200 bytes (indicating successful download).

Step 3: Convert to LZM Files

Once all OSM files are downloaded, convert them to Lezyne LZM format:

# Convert all OSM files to LZM format (one-liner)
for osm in *.osm; do python ../lzm_builder.py --osm "$osm" --bbox auto --verbose; done

This uses the auto bbox detection feature, which extracts coordinates from the filename to determine the map area.

Step 4: Deploy to Device

# Copy all LZM files to Lezyne GPS device
cp *.lzm /Volumes/LEZYNE/Maps/     # macOS
# or
cp *.lzm /media/LEZYNE/Maps/       # Linux

🔧 Troubleshooting

Broken/Incomplete Downloads

If you suspect some OSM files are broken or incomplete, just re-run the download script and normally it will fix the issues.

Expected File Sizes

  • Rural areas: 50-200 KB per OSM file
  • Urban areas: 500KB-2MB per OSM file
  • Final LZM files: 5-200 KB each
  • Empty areas: ~1KB (just XML structure)

📊 Real-World Example

Belgium Coverage: 30,500 km² → 73 grid boxes → 40 minutes download time → 2 ~ 3 minutes LZM conversion → Complete offline coverage
Luxembourg Coverage: 2,586 km² → 12 grid boxes → 10 minutes download time → 1 ~ 2 minutes LZM conversion → Complete offline coverage

💡 Pro Tip: For very large regions, consider breaking them into smaller polygons to manage download times and reduce the risk of interruption. Each polygon can be processed independently and the resulting LZM files combined on your device.
